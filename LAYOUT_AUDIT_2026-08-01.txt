AI Media Studio — LAYOUT AUDIT REPORT
=====================================
Date: 2026-08-01
Flet: 0.86.3
Scope: Audit only (no code changes in this pass)
Auditor: Grok (static inspection of Flet layout trees)

Symptom (reported): tall light-grey empty blocks, endless / extreme scroll,
crushed left rails on multiple tabs. Prior spacing passes reduced some
symptoms but the structural pattern remains inconsistent.


------------------------------------------------------------------------------
0. COLOR VOCABULARY (what “grey” is in this app)
------------------------------------------------------------------------------
From media_studio/flet_theme.py:

  BG             #0f1115  page / darkest
  PANEL          #171a21  primary card/rail background
  PANEL_ELEVATED #1c212b  lighter “slab” (placeholders, text fields, empty boxes)
  BORDER         #2a2f3a

The “light-grey empty rectangle” users see is almost always PANEL_ELEVATED
(or a full-height PANEL rail with no children filling the lower half).
Dark comparison stages use #111318 / #0a0c10 (not the light slab).


------------------------------------------------------------------------------
1. ROOT CAUSE(S) — exact widgets / patterns
------------------------------------------------------------------------------

A. Shell flex chain (all tabs inherit this)
------------------------------------------
page.add → Column(expand=True)
  → main_tabs = Tabs(expand=True)          [flet_app.build_tabs]
    → Column(expand=True)
      → TabBar
      → TabBarView(expand=True)
        → each tab body often Container(expand=True) / Row(expand=True)

Effect: Every primary tab is forced to fill remaining window height.
Any child with expand=True along the vertical axis will compete for that
height. Empty expanders paint as solid grey slabs.

B. Left rail = full-height PANEL + Column(expand=True, scroll=AUTO)
-------------------------------------------------------------------
Pattern (Studio Image, Studio Video, Creative Vision, Tools form host):

  Container(width=FIXED, expand=False, bgcolor=PANEL)
    Column(expand=True, scroll=ScrollMode.AUTO, alignment=START)
      [many controls packing from top]

When viewport height > content height:
  - Content sits at the TOP
  - Remaining vertical space is still PANEL-colored empty area
  - User perceives a “tall grey block under Star / prompt / Generate”

When content height > viewport:
  - Scroll works, but long builders + region + frames make “endless” feel

This is NOT necessarily an invisible spacer widget; it is the stretched
rail background itself.

C. Nested scroll (Tools / dual cards / Audio)
---------------------------------------------
Tools:
  Tools.build Column(expand=True)
    → _tool_host Container(expand=True)
      → Row(expand=True, STRETCH)
        → left Column(scroll=AUTO, expand=True)
          → form root Column(scroll=AUTO)   # DualMediaToolCard / Sharpen / etc.

Two scroll viewports on the same content = scroll fighting, content
appearing “far away,” or only one layer scrolling while the other paints
empty height.

Audio Music:
  _audio_host Container(expand=True)
    → Column(scroll=AUTO, expand=True)
      → music_card (PANEL) with long builder → long single scroll (OK-ish)
        but host still full-height PANEL/page void around/under card.

D. Horizontal split: fixed left + expand right
----------------------------------------------
Intended (after prior fixes):
  left:  width=RAIL_WIDTH (460) or TOOLS_FORM_WIDTH (560) or Vision max(RAIL,480)
         expand=False
  right: expand=True  (takes all remaining width)

Why right “owns” the window when empty:
  - Right is supposed to flex; empty result still gets (window − left − chrome)
  - Empty state widgets may be only ~96px tall, so most of the right pane is
    empty PANEL surface (large grey field) even if not a false “expand Image”

Why left can still feel crushed:
  1. Fixed 460–560px on a 4K/wide monitor looks like a thin strip vs huge right
  2. Historical: Frame Editor previously had left expand=True in a Row
     (horizontal flex fight) — currently expand=False, width=420
  3. Tools dual-upload used to put 3 columns in ~480px (fixed in structure
     to stack, but any remaining side-by-side rows with expand children can
     still squeeze labels)
  4. Flet Dropdown expand=True inside a Column is VERTICAL flex — still a
     risk wherever a sole-dropdown is not wrapped in a Row

E. Right-side expand trees that stay large when empty
-----------------------------------------------------
Studio Image comparison:
  right panel(expand=True)
    Column(expand=True)
      Row(expand=True)
        compare_rail: Column(expand=True) including _versions_col(expand=True)
        workspace: Column(expand=True)
          overlay_placeholder (h=96, PANEL_ELEVATED)  ← light grey box
          overlay_stage (expand toggled; dark when active)

Even with placeholder height 96, the parent Columns/Rows still expand to
full pane height → large empty PANEL around the small placeholder.

ToolsResultPane:
  root panel Column(expand=True)
    Row(expand=True) → workspace Column(expand=True)
      placeholder (h=96, PANEL_ELEVATED)
      stage expand only when result exists
      video_player.control (compact when empty after last fix)

Creative Vision right:
  panel(expand=True) Column(expand=True)
    result_image (height=280, visible=False when empty)
    player.control (VideoResultPlayer, height≈EMPTY_PREVIEW_H+40 when empty)

F. VideoResultPlayer history
----------------------------
Previously: Container(expand=True) + placeholder Column(expand=True)
  → classic full-height grey void on every host.

Current (flet_video_player.py): expand=False, fixed empty height.
  Residual risk: if a parent forces expand on the control at runtime, or
  height is overwritten (Frame Editor sets control.height = _PREVIEW_H).

G. Dropdown expand=True semantics (Flet)
----------------------------------------
styled_dropdown(..., expand=True) sets Dropdown.expand.
- Inside a Row: horizontal grow (intended).
- Inside a Column: vertical grow (unintended tall empty control chrome).

Any remaining sole-column Dropdown with expand=True reintroduces slabs.

H. Double tab nesting (Studio only)
-----------------------------------
main TabBarView → Studio tab → nested Tabs (Image | Video) → TabBarView
  → another expand=True body.

Adds another flex layer and can lag off-screen updates (code already notes
TabBarView lag for Video).

3. HORIZONTAL SPLIT — current behavior
------------------------------------------------------------------------------

Constants (flet_theme.py):
  RAIL_WIDTH        = 460
  TOOLS_FORM_WIDTH  = 560
  EMPTY_PREVIEW_H   = 96

Tab           Left width     Left expand   Right expand   Notes
-----------   ------------   -----------   ------------   -----
Studio Image  460            False         True           Right eats remainder
Studio Video  460            False         True           Same
Creative Vis  max(460,480)   False         True           Same
Frame Editor  420            False         True           Narrower left
Tools form    560            False         True           Nested under header
Audio         full width     n/a           n/a            Single column

Collapse mechanism (when it happens):
  - Not usually width=0; it’s relative: left fixed px vs huge right flex.
  - True crush was multi-column forms + Dropdown expand in tight width.
  - Row children with expand=True on left+right both (historical FE) would
    share horizontal space and ignore fixed width — currently FE left is
    expand=False (correct for width).

Grey slab under Star/prompt:
  Primary mechanism = left Container full height (STRETCH from parent Row)
  + Column content shorter than that height → empty PANEL band.
  Secondary = nested scroll making controls feel “below the fold.”

4. THE LIGHT-GREY RECTANGLE — what control is it?
------------------------------------------------------------------------------

Most common matches (PANEL_ELEVATED #1c212b):

1) Empty placeholders (fixed height, intentional “box” look)
   - Studio Image: source_placeholder; overlay_placeholder (“Generate to compare”)
   - Vision: start_ph / end_ph (“Start still” / “End still”) on the LEFT rail
   - ToolsResultPane.placeholder (“Generate a result to preview full-size”)
   - VideoResultPlayer.control when empty (elevated border box)
   - Region: preview_placeholder; dual-tool placeholder thumbs

2) Full-height rail / pane fill (PANEL #171a21, still reads “grey slab”)
   - Left Container bgcolor=PANEL stretched to tab height with content only
     at top (no separate child — the empty is the container itself)
   - Right panel(expand=True) with only a small elevated placeholder

3) NOT usually: result preview “misplaced on the left”
   - Vision frame thumbs are intentional left-rail controls (120×80).
   - True result stages live on the right (comparison / ToolsResultPane /
     Vision result_image / FE preview_box).

4) TextField / Dropdown fill (also PANEL_ELEVATED)
   - Prompt boxes look like large grey rectangles when multiline min_lines
     is high; not expand voids, but add visual mass and scroll length.

Dark voids (#111318) are comparison/stage/preview_box — different complaint
but same “empty owns the viewport” class.

5. RECOMMENDED FIX PLAN (ordered, concrete — do not implement in this pass)
------------------------------------------------------------------------------

Adopt ONE structural pattern for all “tool-style” and “studio-style” tabs:

  Pattern name: FixedRail + CapRightEmpty

  Row(expand=True, vertical_alignment=STRETCH)
    left: Container(
            width=RAIL,           # 460–520
            expand=False,         # NEVER horizontal expand in a Row
            bgcolor=PANEL,
            content=ListView(     # prefer ListView over Column(scroll)
              controls=[...],     # every control real; no expand spacers
              expand=True,        # only the ListView fills height
              padding=...,
            ),
          )
    right: Container(
            expand=True,
            alignment=TOP_LEFT,
            content=Column(
              tight=True,
              expand=False,       # content-sized when empty
              controls=[
                header,
                empty_placeholder height=EMPTY_PREVIEW_H  OR real stage,
                actions,
              ],
            ),
          )

When right has real media: set stage.expand=True (or fixed large height)
and call page.update — do not leave expand=True on empty parents.

Ordered steps
-------------
1) Shell / build_tabs (flet_app.py)
   - Confirm TabBarView children are only the tab roots with expand=True once.
   - Avoid double Container(expand) wrappers around views that already expand.

2) Extract shared helper (new small module or flet_theme)
   - e.g. make_split_workspace(left_controls, right_controls, left_width=…)
   - Enforce: left ListView; right Column tight; no dual scroll.

3) Studio Image (flet_app.StudioImageView.build)
   - Replace left Column(scroll) with ListView of the same children.
   - Right: do not use nested Column(expand)+Row(expand)+workspace(expand)
     when empty; only expand workspace/stage when comparison has paths.
   - Optionally collapse compare_rail when no versions.
   - Keep multi-ref panel, region_panel, overlay stage behavior.

4) Studio Video (flet_video.StudioVideoView.build)
   - Same ListView left pattern (lower priority; already shorter).
   - Right: keep VideoResultPlayer non-expand empty.

5) Tools (flet_tools.ToolsView + flet_tools_result + flet_dual_tool)
   - ONE scroll: either form Column scroll OR host Column scroll — not both.
   - Keep stacked media+form layout for Sharpen / Match Look / Sky.
   - ToolsResultPane: root Column expand only when result present; empty =
     tight header + 96px placeholder; no workspace Column(expand=True) empty.

6) Creative Vision (flet_vision.CreativeVisionView.build)
   - ListView left; move optional ExpansionTiles / heavy frames below the fold
     but keep Generate above them (already).
   - Right empty: tight Column, no expand=True Column fill.
   - Keep start/end thumbs fixed 120×80 (document as left controls, not result).

7) Frame Editor (flet_aleph.FrameEditorView.build)
   - Already ListView left — good.
   - Reorder or sticky-footer Generate (cost+Generate always visible without
     scrolling past filmstrip-related mental model) — careful not to break
     keyframe workflow.
   - preview_box keep fixed height; result_player height=0/hidden when unused.
   - Align left width with RAIL_WIDTH (460) for consistency.

8) Audio (flet_audio)
   - Host Column expand with alignment START is OK; ensure music_card does not
     use expand TextFields; single scroll only.
   - Optional max-width card centered so ultra-wide doesn’t feel empty.

9) Regression checklist after fix
   - Multi-ref Assign UI (Studio Image)
   - Comparison overlay / A/B / region stage overlay
   - Filmstrip + keyframes (FE)
   - Tools Send-to / before-after
   - Library header tight + ListView-only expand
   - Generate / Enhance / Run reachable with normal scroll

Do NOT:
  - Fix by nesting more ExpansionTiles that hide primary actions
  - Give both left and right expand=True in a Row
  - Use Dropdown expand=True as sole child of a Column
  - Leave Column(scroll) parent of another Column(scroll)

8. TOP FINDINGS (executive)
------------------------------------------------------------------------------
1. The grey “void” is often the stretched PANEL background of a full-height
   left/right Container, not a mysterious orphan Image — content is top-
   aligned inside expand=True parents.

2. Nested expand trees on the right (Column→Row→Column all expand=True) keep
   empty result areas full-window even when the visible placeholder is only
   ~96px.

3. Nested scroll (Tools form scroll inside host scroll) produces “endless
   scroll” and unreachable Run/Generate feelings.

4. Horizontal split is fixed-left + flex-right by design; empty right will
   always look dominant on wide monitors unless empty right is content-sized
   and left is widened or given proportional min width.

5. Vision left start/end PANEL_ELEVATED boxes are normal controls, frequently
   misread as broken result previews.

6. One shared pattern (ListView left, tight right until media exists, single
   scroll) should replace the ad-hoc Column(scroll)+expand combinations.
